rld

Claims: 21

rld is the runtime linker for IRIX, equivalent to ld.so on Linux and other Unix systems, where it determines where programs run and manages shared libraries during runtime. 12 It is not part of the kernel, which is not really aware of dynamic libraries, and the IRIX implementation is partially in the shared C library and part of the ELF implementation, making truly statically linked binaries impossible. 345 rld uses internal interfaces such as _rld_new_interface for functionality like dladdr, and this symbol exists even if it is not present at link time. 67 GNU binutils can produce a shared library that rld cannot successfully relocate under certain conditions, and the error rld: Error: unresolvable symbol in /usr/lib32/libGLcore.so: __rld_obj_head occurs when using the -Wl,--version-script,binary.ver option. 89 rld ignores an undefined symbol named gl_INTERPRET_END in libGLcore.so and libgl.so without causing runtime issues, because both libraries have a symbol gl_INTERPET_END with a value, which can make rld and older linkers like mipspro ld ignore undefined symbols. 1011 rld does not honor library replacement or other rld environment variables for setuid and setgid programs unless the user is root. 12 It requires code conforming to the IRIX ABI, and lld can be configured to emit such code. 13

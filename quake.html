Quake

Claims: 96 Background: 21 claims already covered by Wikipedia, see Quake (video game), SGI Octane.

Quake is extremely ported, with ports available for multiple SGI architectures including x86, PowerPC, MIPS, ARM, SuperH, and Itanium. 12 The Quake source includes ports/makefiles for various UNIX distributions like IRIX and Solaris, as well as a generic X11 port and the original DOS VGA port. 3 Quake has an official port for SGI systems, though the original ones are considered garbage. 45 Quake can be built from source on HP-UX, even if it uses software rendering, which performed poorly. 67 Quake can be configured to use less heap memory, as it seems to be requesting more than necessary. 8 Quake is heavy on the FPU, which was buggy in early Pentium chips. 9 Quake can be compiled to support SMP, which is currently disabled in existing ports. 10 Quake's high fill rate and use of the FPU make it demanding on hardware, with texture mapping and performance depending on graphics cards, texture RAM, and CPU capabilities. 111213 Various software ports and patches exist for Quake, including ioQuake3, DarkPlaces, and SGIQuake, though some versions have compilation or runtime issues on certain systems. 14151617 Some users desire enhanced Quake versions with features like gouraud/phong shading, transparent water, and hardware 3D acceleration, while others note that modding can produce shaded surfaces without textures. 18192021 Quake was developed on Next hardware, while its successor ran on Nextstep running on Intel. 22 Quake runs on an FPGA mod inside an Amiga, and running Quake on a PiStorm on RTG is technically still an Amiga. 2324 Quakespasm is an open-source port of the Quake engine for IRIX, and TyrQuake is a fully up to date bug fixed Quake source port with OpenGL v1 support, focusing on performance on low-end systems. 2526 Licensing for the Quake engine requires payment if you want to keep your source code private. 27 Quake does not support multipipe configurations, making it difficult to benchmark the Infinite user-24f0. 28 Quake requires kernel tuning parameters to run on IRIX 6.5.30, unlike 6.5.22, and requires kernel tuning to run on VPro machines, but not on other SGI systems. 2930 Quake is not highly optimized for SGI systems, prioritizing accuracy and high-end features over raw frame rate. 31 Only SGI quake works with o2, darkplaces only works with odyssey, and nothing works on octane Mgras. 32

/etc/passwd

Claims: 17 Background: 1 claim already covered by Wikipedia, see Bash (Unix shell).

Editing /etc/passwd can change a user's default shell by setting the last field to the path of bash, then logging out and back in, or by using the vi editor to make the change (including clearing a password hash by setting it to ::). 12 This can be done by starting an installation and using the admin menu to open a shell, booting miniroot from the network, or booting into single user mode, which on IRIX requires a second disk and then mounting the root disk. 345 On IRIX, editing /etc/passwd in single user mode can clear a forgotten password, and the system uses /etc/passwd without a shadow file by default, storing the password hash directly in the file. 678 The IRIX system uses a specific hashing mechanism for passwords, and a corrupted /etc/passwd with a messed-up hash can prevent a machine such as an Octane from starting, which may be fixed by restoring an old /etc/passwd file. 89 On macOS, changing the user shell requires modifying a plist file rather than /etc/passwd. 10 The login window excludes accounts with a locked password field in /etc/passwd, and checking the file might reveal information about the system's configuration. 1112 Editing /etc/passwd directly can cause issues with system files, and modifying the root user's home directory to point to /root/ ensures /root/.cshrc is used instead of /.cshrc, though incorrect paths can cause issues with sudo and other commands. 1314 /etc/passwd contains an entry for the demos user, and there is an .icons directory in /usr/demos with relevant files. 15

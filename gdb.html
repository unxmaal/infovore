gdb

Claims: 52 Background: 18 claims already covered by Wikipedia, see GNU Debugger, Dbx (debugger), Ghidra.

gdb is a debugger that can print backtraces and show the call stack to help diagnose issues. 12 gdb can debug binaries compiled with gcc and mipspro, and can be used for GCC-compiled code, though it is not reliable with binaries created using the latest gcc8 build. 345 gdb works well with binaries built using gcc4, but Merijn's gcc-4.6.1 generates binaries that could not be debugged with the included GDB. 67 gdb has limited support for threads on IRIX, and may not be effective for debugging pthreads issues. 8910 gdb can be run on a binary from within the build tree of an autotools project using 'libtool --mode=execute gdb'. 11 gdb can have issues with IRIX 6.5.22, including infinite loops when stepping into libc calls. 12 gdb on IRIX does not properly support ptrace for stepping and other debugging tasks. 13 gdb can be compiled with the -g flag. 14 GDB is a symbolic debugger for C/C++ that works well but has issues with 16-bit x86 code through qemu stubs. 15 It offered support for Unix systems, with better performance when using GCC. 16 GDB has issues with pthreads and other things built with GCC, and dbx has problems with GCC-built programs. 17 GDB can be used to debug MIPS applications by running specific commands like `bt`, `info registers`, and `disassemble` when the program bus errors, and it can be used to debug a program that segmentation faults. 1819 GDB on IRIX only works by accident and isn't good at debugging C++ code, and it isn't very good at driving processes with ptrace on IRIX. 2021 Using gdb or ddd on the IRIX port results in the program hanging without responding to CTRL-C until it crashes. 22

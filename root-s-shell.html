root's shell

Claims: 4

On Solaris pre-10, root's shell must be set to /sbin/sh to avoid issues with the shell not being executable; this is fixed in 10. 1 Changing root's shell to /usr/sgug/bin/bash can break stuff if it relies on libraries or binaries not on /. 2 Root's shell should not have funky replacements for standard system utils in its PATH to avoid flummoxing init scripts. 3 On Solaris versions before 10, changing root's shell can lead to a shell that can't run with /usr unmounted, causing issues in single user mode. 4

Sources

  1. On Solaris pre-10, root's shell must be set to /sbin/sh to avoid issues with the shell not being executable; this is fixed in 10. (user-7b1c, 2020-04-15, exchange 74066, check: supported)
  2. Changing root's shell to /usr/sgug/bin/bash can break stuff if it relies on libraries or binaries not on /. (user-15a0, 2022-11-08, exchange 217771, check: uncheckable)
  3. Root's shell should not have funky replacements for standard system utils in its PATH to avoid flummoxing init scripts. (user-7b1c, 2022-11-08, exchange 217771, check: uncheckable)
  4. On Solaris versions before 10, changing root's shell can lead to a shell that can't run with /usr unmounted, causing issues in single user mode. (user-7b1c, 2022-11-08, exchange 217771, check: supported)

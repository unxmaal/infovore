X server

Claims: 55 Background: 1 claim already covered by Wikipedia, see OpenGL.

The X server can be started on a machine, allowing a GUI session to be accessed from a remote host via XDMCP and an X server launched with the '-query' option. 12 The X server may not always honor the requested color depth, and it can use different visuals with their own bit depth for different windows even if the root window is set to a specific bit depth. 345 On SGI hardware, the X server can set different color depths for different applications during scanout, unlike PC hardware where the color depth setting applies to all applications. 6 The X server from HP-UX 11.11 can be force-installed on 11.23 to make the Visualize FX10 work, though missing fonts need to be resolved, and the SGI acts as the X client expecting extensions that can vary between implementations. 78 Integrating newer technology with the SGI X server is difficult, and Atom definitions allow building modern clients that depend on assumptions about X server capabilities, but these assumptions fail because the required features are not actually present. 910 Each process calling XOpenDisplay opens a new socket and a new connection to the X server. 11 The X server supports varying color depths on SGI hardware, and setting it to 24-bit color wastes more memory, provides more colors for wallpapers, and affects the color depth of applications that use `CopyFromParent`. 1213 The X server must be set to 24-bit color for the application to launch, as it does not request the visual correctly. 14 IRIX sessions can crash, logging users back to the login screen, often due to an X server crash. 15 The Tezro shows graphics in PROM but not after installing Unix.IP35, which requires booting IRIX to see the X server, while the Onyx4 does not show graphics until the X server boots, not even in PROM. 1617 Emulating hardware can significantly reduce CPU usage by intercepting the libGL/libIrisGL layer and providing an in-process X server. 18

.profile

Claims: 8

  • shell startup scripts can be added by creating a .bash_profile or .profile in the user's home directory. (user-42cf, exchange 202, 2019-01-23; 1 speaker(s), 1 conversation(s))
  • Login shells run .profile and non login shells run .bashrc; sourcing .bashrc from .profile ensures it runs for both. (user-6afa, exchange 69028, 2020-08-21; 1 speaker(s), 1 conversation(s))
  • Adding a 'stty rows 25 cols 80' line to .login, .profile, or .cshrc sets terminal size, and setting TERM, MANPATH, EDITOR, BROWSER in these files configures the environment. (user-c831, exchange 98671, 2021-04-02; 1 speaker(s), 1 conversation(s))
  • yes. and you need to reload .profile like with . .profile or restarting the shell (user-d5ee, exchange 240353, 2024-08-10; 1 speaker(s), 1 conversation(s))
  • .cshrc is a configuration file for the C shell; .login is a login script that does various things; .profile is run if the shell is /bin/sh or possibly bash. (user-6dfb, exchange 50729, 2024-11-21; 1 speaker(s), 1 conversation(s))
  • Check .profile, .bashrc, or .cshrc to set PATH, and modify the current shell session to test the change. (user-21b8, exchange 215548, 2024-08-15; 1 speaker(s), 1 conversation(s))
  • MacPorts adds paths to .profile, but they are not reflected in $PATH when using zsh; moving the export command to .zshrc fixes it. (user-17cb, exchange 144640, 2021-01-19; 1 speaker(s), 1 conversation(s))
  • Running bash as a shell wipes the environment, but sourcing .profile or running bash -l fixes it. (user-f229, exchange 80928, 2022-02-09; 1 speaker(s), 1 conversation(s))

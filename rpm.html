RPM

Claims: 73

RPM is a package management system that is considered a decent package manager, handling dependencies and installation order, and is regarded as better than a source port system or Tardist, though it is not a very good solution and was hated by users as notorious bloatware even on early Linux. 1234 RPM can be built on various platforms, including Alpha using DEC compilers and used on Tru64, runs on IRIX64 6.5, and requires C11 features like __thread and __alignof__, so it must be built with gcc rather than MIPSPro. 567 rpm needs specific tools to build packages, can complain about binary architecture mismatches, does not have out-of-box auto dependency management, and relies on external tools like yum for dependency resolution. 89 To build RPM packages, one can download the source RPM, modify the spec file, and use rpmbuild with --nocheck, and rpm can use multiple CPUs for building packages based on the host's CPU count unless overridden. 1011 rpm provides repeatable builds with defined rules in spec files, making porting easier and more reliable, and includes an embedded LUA interpreter. 1213 rpm can force the installation of a newer package that conflicts with an older one, but this may require removing the old package first, and rpm -q --whatprovides can help identify where files come from, though it's not always accurate. 1415 RPM is planned for future implementation and may replace the current setup over time, with SGI using existing tools like rpm to create tardist packages rather than reinventing the wheel. 161718 RPM is a package management system used by several operating systems and distributions, including RSE (based on FC31), SGUG stuff (from 5.1L), and AIX. 19202122 RPM builds software from a SPEC file, which is a build script, and existing spec files can be used as a starting point for creating RPMs. 2324 To build an RPM from Fedora source, install the SRPM, copy the spec file, and run `rpmbuild -ba`; the resulting RPM can then be installed. 25 When installing source RPMs with `rpm -ivh`, the spec files are installed in the user's home directory unless run as root, where they go in /root/rpmbuild/SPECS; this can be changed by setting the rpmbuild home directory. 26 An RPM based environment using up to date versions of gcc has been developed, and RPM packages can be built on IRIX by setting up RPM environment variables and folders, installing the SRPM, and running `rpmbuild -ba` on the spec file, which may fail initially and require patches. 2728 RPM and other package managers can be difficult to use, and packaging for SGI systems using tardist or RPM is challenging. 2930

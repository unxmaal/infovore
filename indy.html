With O2

The Indy is generally cheaper than the O2, but the O2 is faster, being faster than the Indy even in its worst configuration. 12 The O2 is one of the cheapest SGI systems, with the Indy being the next model and substantially slower. 3 The O2 is the successor to the Indy and has more potential. 4 The O2 is easier to set up than the Indy and Octane, with an internal CD, no 13W3 adapters, and being faster. 5 The O2 has pretty much unlimited texturing and up to 1GB of memory, and even an 180MHz O2 is faster than an 180MHz Indy because of faster memory. 6 The O2 is criticized for being slow but is better for media than the Indy and Fuel. 7 The O2 and Indy are made of plastic, with the Indy's being particularly durable due to its need to support a heavy CRT. 8 The installation process for the Indy is similar to that of the O2, Octane, Fuel, Onyx3, and Indigo2, as they all use the same Numaflex architecture. 9 The R5000 processor in the Indy is not pin-compatible with the R5000 in the O2. 10 During the installer process, the Indy locks up while the O2 gets stuck with a hard disk not ready error. 11 The O2 and Indy labs were later replaced with IBM PC workstations. 12 The Indy has issues with the 1600SW display on the O2, and the menus may crash when opened; moving the resource file to the X11 app defaults folder can resolve these issues. 13 The speaker still has Indy and O2 bugs and features to address. 14 The NEC EA193Mi 19" LCD monitor works well for the O2, Indy, Indigo, and older Indigo2. 15 The Octane is the most stable platform among the O2, Indy, and Octane. 16

With Indigo2

The Indy and Indigo2 are SGI systems that share some hardware characteristics, including the same R4K RAM for the Indigo 1, and compatible specifications for the Indy motherboard and graphics chips. 1718 They use PS/2 keyboards and mice, which are compatible with all SGI systems from Indigo2 and Indy onward. 1920 The Indy is larger than the Indigo2, which is lighter, and both were designed for monitor-on-top use. 212223 The Indy and Indigo2 offer XL graphics as a low-end option, with the same chips but different board layouts. 24 They do not have a DSP, with audio supported by a combination of code running on the CPU and an audio ASIC chip. 25 The Indigo2 and Indy use SD cards for emulated SCSI, offering faster random access, and SCSI2SD v6 works fine in the Indy and Indigo2. 2627 The Indy plays nicely with SCA adapters, but the Indy's SCSI bus is too slow to worry about the I/O performance boost that SCA provides on a faster machine. 2829 The Indigo2 and Indy are incompatible when left alone together, and the XZ in the Indy is different from the XZ in the Indigo and Indigo2. 3031 Indigo2, Indy, and Indigo2 Teal Impact are recommended alternatives that run the same software, and the Indy and Indigo2 can run up to IRIX 6.5.22. 323334 The Indigo2 is more compact and lighter than the Indy and loads programs about five to ten times faster. 3536 The Indy and Indigo2 use standard 72-pin FPM parity SIMMs, and the Indy has easier video hardware for input. 3738 An Indy or Indigo2 with a dead PSU was considered worthless compared to a modern Octane or O2, and the Indy and Indigo2 became the O2 and Octane, respectively. 3940

With Octane

The Indy and Octane are the most common SGI machines by a landslide, with the Indy being a volume-seller until the Octane gained traction. 4142 The Indy uses a 50-pin connector, while the Octane uses a wider 68-pin connector. 4344 The Octane's backplane slots are tricky, unlike the Indy or Indigo, which are more user-friendly for retrofits. 45 The Indy uses regular signal, unlike the Octane, which uses sync on green. 46 An Indy running on 5.3 can mount an NFS drive from an Octane over the network, and forwarding IrisGL from an Indy running Irix 5.3 to an Octane allows running old COFF IrisGL applications on a more powerful machine. 4748 The Octane is recommended for running textured polygons and for writing SGI software, as an Indy might struggle. 495051 Booterizer can be used to install IRIX on an Octane and possibly an Indy. 52

With MAME

MAME can emulate an Indy, which is useful for running old software on newer hardware, though performance depends on hardware and the emulation is slow and not perfect. 535455 The Indy's performance in MAME improved with newer releases, making it more viable for emulation, and MAME defaults to 256 MB RAM, though 16 MB is below the Indy's minimum RAM. 5657 The TAP/TUN driver with OpenVPN allows network adapter selection in MAME on an Indy, but the Indy's networking might not work and using MAME for networked IRIX might be a bad idea. 585960 Setting the eaddr and configuring IP in IRIX is required after loading the TAP/TUN driver and connecting an adapter to MAME. 61 The patched version of MAME allows the Indy to start up, but it crashes during framestore initialization. 62 MAME 0.240 is suitable for compiling but lacks networking, and multigen works with minor bugs on MAME, with menus lacking background images compared to a real Indy. 6364 The Indy's networking might not work in MAME, and the Indy requires specific keyboard input settings in MAME. 5965 plan9/9front includes an Indy source port, and these specs were released to support open source development on the Indy; without them, MAME would not support the Indy. 66

With IRIX 5.3

The Indy can run IRIX 5.3, but may crash with newer versions of the operating system. 67 The Indy is a 4600, 8-bit machine with two HDDs, one being 1GB, when running IRIX 5.3. 68 The Indy struggled to run IRIX 5.3 with 16MB of RAM, so SGI upgraded all base models to 32MB shortly after. 69 Installing IRIX 5.3 on an Indy requires a specific tutorial, and issues may arise if the wrong block size is not specified. 70 A 2GB drive was typical for an Indy running IRIX 5.3. 71 IRIX 5.3 was optimized for 64MB of RAM and performed better than 5.1 on an Indy with 32MB. 72 The Indy can run IRIX 5.3 due to its limited RAM, but it lacks Nekoware and SGUG-RSE. 73 An Indy running IRIX 5.3 may crash and not reboot, possibly due to a faulty SCSI adapter or PSU issues. 74

With Indigo

The Indy and Indigo were contemporary machines that required deep working knowledge of every subsystem to operate. 75 Floptical drives were standard on most Indys and Indigos, and were not typically regular floppy drives. 76 The Indigo had proper accelerated 3D graphics options, while the Indy did not until the XZ. 77 The R5k in an Indy is faster than an Indigo unless doing 3D. 78 Even the cheapest Indy compares well with an Indigo. 79 The Indigo stores the MAC address in an EEPROM on the backplane, while the Indy uses a Dallas chip, and the Indy does not enter a 'cannot set TOD clock' loop when the MAC address cannot be set. 80 There is no jumper to reset the password on Indigo or Indy. 81 Indy and Indigo were only modern machines with 8-bit options; no Indigo2 boardsets had 8-bit. 82

With R5000

The first Indy used a 100 MHz R4400 CPU, while 180 MHz was an R5000. 83 An Indy can use an R5k processor for potentially better performance, and there is an Indy available for upgrade with a R5000 CPU. 8485 The R5k is included in an Indy system and runs Irix. 8687 An Indy with a R5000 should maintain 24-bit graphics capability, and most R5K Indys come with XL24 graphics. 8889 The 24-bit Newport video chipset is recommended for R5K on the Indy. 90 An Indy with an r5k can run Doom and Quake1. 91 Blender works on an Indy R5000 for animation and rendering tasks can be offloaded to a more powerful machine on the network. 92 An Indy with an R5k CPU is operational after installation. 93

With IRIX

The Indy requires a user to run a command in the boot PROM before installing IRIX, and the installation can be automated. 9495 QEMU can run an older version of IRIX on an emulated Indy, and an IRIX install can be booted on an SGI Indy with a modern(ish) *NIX. 9697 The Indy was a low-end machine, and IRIX was not designed with corner cutting in mind, so the base requirements were already challenging at the Indy's price point. 9899 The Indy had insufficient RAM for new IRIX releases, requiring a base RAM increase. 100 The Indy is slow at building packages on IRIX. 101

With IRIX 6.5.22

The Indy supports IRIX 6.5.22. 102 An Indy running IRIX 6.5.22 can be slow, possibly due to its R4600 CPU or being defective. 103 Booterizer was used for IRIX 6.5.22 installation on an Indy without a SCSI CDROM drive. 104 The IRIX 6.5.22 installer may hang if the CPU speed is overclocked. 105 ZuluSCSI maxes out the bus on the Indy and runs well with 128 MB RAM; IRIX 6.5.22 runs well with 128 MB, but page swaps with 32 MB. 106 On an Indy with 64 MB of RAM running IRIX 6.5.22, ZuluSCSI Wide performance can be severely impacted, making the system borderline usable. 107 Converting an Indy IRIX 6.5.22 image from xl to xz graphics may result in conflicts and require a reinstall. 108

With IRIX 6.5

The Indy can run IRIX 6.5, though the drive was originally 5.1. 109 An Indy with an R4400 CPU and 1GB of RAM can take up to three minutes to load IRIX after logging in, requiring patience during boot. 110111 IRIX 6.5 on a real Indy is like running Windows 2000 on a 486 already. 112 The Indy can come with an R4400 CPU and includes documentation and IRIX 6.5 media. 113 Running Alias/1 on an Indy with IRIX 6.5 is not possible. 114
